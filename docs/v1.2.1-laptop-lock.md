# Regnant v1.2.1 — Workstation Lock Architecture & Security Boundary

## 1. Overview

Regnant provides a one-touch, confirmed workstation lock capability from the Android Home screen. This allows the user to immediately secure their Omarchy Linux computer upon stepping away.

---

## 2. Security Boundary & Non-Negotiable Principle

> [!CAUTION]
> **Strict Security Boundary: One-Way Remote Lock Only**
> - **Regnant NEVER stores, transmits, or accepts user login passwords or credentials.**
> - **Regnant CANNOT unlock the workstation remotely.**
> - Unlocking the laptop strictly requires physical presence and manual authentication on the laptop keyboard (password entry) or biometric sensor (fingerprint reader).
> - There is no remote unlock API, no password escrow, and no backdoor into PAM/display-manager authentication.

This security architecture ensures that even in the unlikely event an Android device is lost or compromised, the physical computer cannot be decrypted or unlocked over the network.

---

## 3. Omarchy Linux Lock Subsystem

### 3.1 Lock Execution (`linux/host/src/power.js`)
When a lock request is authenticated:
1. Regnant checks for the presence of `/usr/share/omarchy/bin/omarchy-system-lock`.
2. When present, it executes `/usr/share/omarchy/bin/omarchy-system-lock` directly, which:
   - Invokes `omarchy-shell lock lock` to engage the Omarchy Wayland lock screen.
   - Resets keyboard layout to default (`hyprctl switchxkblayout all 0`).
   - Locks 1Password vault (`1password --lock`).
   - Terminates running screensavers and screen video players (`ttfx`).
3. If `/usr/share/omarchy/bin/omarchy-system-lock` is absent, it falls back to systemd logind standard lock:
   `loginctl lock-session`.

### 3.2 Lock Status Telemetry
Regnant queries lock status via `getLockStatus()` in `linux/host/src/power.js`:
- Checks `omarchy-shell lock isLocked` (returns `'true'` or `'false'`).
- Falls back to `loginctl show-session $XDG_SESSION_ID -p LockedHint`.
- Broadcasts updates to Android over WebSocket and responds to `GET /api/v1/power/lock-status`.

## 4. Android User Experience & Confirmation Flow

### 4.1 Visual Placement
The previous unlabeled lock icon in the mini hardware telemetry banner was replaced with a dedicated, distinct button:
- **Label**: `[ 🔒 Lock Laptop ]` with high-contrast Coral border and text.
- **Position**: Integrated seamlessly on the right side of the hardware telemetry row directly below the workspace selector.

### 4.2 Explicit Confirmation Modal
Tapping the button displays an explicit confirmation dialog:
- **Title**: `Lock <laptop-name>?` (dynamically resolves the connected machine, e.g. `Lock electron (Omarchy)?`).
- **Explanation**:
  > *"Your laptop screen will lock immediately.*
  > *Unlocking requires physical entry of your password or fingerprint directly on the computer. Regnant cannot unlock your workstation remotely."*
- **Actions**:
  - `Cancel`: Closes modal without performing any action on the laptop.
  - `Lock`: Dispatches `client.lockWorkstation()` over HTTPS / WebSocket.

### 4.3 Visual Feedback
Upon successful execution, Android displays a native transient toast:
`"Laptop locked"`
The persistent host service remains active on port 53317, maintaining background connectivity.
