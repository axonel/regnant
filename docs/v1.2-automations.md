# Regnant v1.2 — Automations & Scheduled Actions
## Typed Event Bus, Cooldown Deduplication & Persistent Heartbeat Scheduler

Regnant v1.2 introduces an **Automation & Scheduler Engine** that links hardware events, mobile triggers, and recurring workstation routines together without needing external cloud automation services (like IFTTT or Zapier).

---

## 1. Event-Triggered Automation Subsystem (`AutomationEngine`)

Located in `linux/host/src/automations/engine.js`:

- **Typed Event Registry**:
  - `DEVICE_CONNECTED`: Fired when an authorized mobile phone establishes WebSocket connection.
  - `DEVICE_DISCONNECTED`: Fired when a paired device disconnects or times out.
  - `AGENT_COMPLETED`: Fired when a local coding agent exits.
  - `DOWNLOAD_COMPLETED`: Fired when a browser or file transfer finishes.
  - `BATTERY_CRITICAL`: Fired when laptop battery falls below 15%.
  - `WOL_RECEIVED`: Fired when a Wake-on-LAN magic packet arrives.
- **Deduplication & Cooldown**:
  - Maintains a sliding window cooldown (default 5000ms) per rule to prevent cascade re-triggering.
- **Actions**:
  - `ROUTINE`: Triggers a registered multi-step routine.
  - `MUTE_AUDIO`: Toggles audio mute via PipeWire `wpctl`.
  - `NOTIFY`: Sends a desktop notification via `notify-send`.
  - `LAUNCH_APP`: Starts an approved allow-listed application.
- **SQLite Persistence**: Stored in `automations` table with rule metadata, conditions, and enablement flag.

---

## 2. Heartbeat Scheduler Subsystem (`Scheduler`)

Located in `linux/host/src/scheduler/scheduler.js`:

- **Execution Model**:
  - Heartbeat timer runs every 30 seconds (`setInterval` tick).
  - Queries SQLite `schedules` table for active jobs where `next_run_at <= Date.now()`.
  - Executes matched actions and updates `last_run_at` and `next_run_at` accordingly.
- **Schedule Types**:
  - `INTERVAL`: Recurring timer running every N seconds (e.g., 3600 for hourly).
  - `ONCE`: One-off delayed action at a specific epoch timestamp.
- **Failure Resilience**: Unhandled exceptions in individual scheduled jobs are caught and logged without crashing the scheduler daemon.

## 3. Protocol & REST Endpoints

- `GET /api/v1/automations`: Returns all registered automation rules.
- `POST /api/v1/automations/save`: Create or update an automation rule:
  ```json
  {
    "id": "rule-1794914000",
    "name": "Mute On Connect",
    "trigger_type": "DEVICE_CONNECTED",
    "action_type": "MUTE_AUDIO",
    "enabled": 1
  }
  ```
- `POST /api/v1/automations/delete`: Removes a rule by id.
- `GET /api/v1/scheduler`: Returns all scheduled tasks.
- `POST /api/v1/scheduler/save`: Create or update a scheduled task.
- `POST /api/v1/scheduler/delete`: Removes a scheduled task by id.

---

## 4. Mobile Client Interface (`AutomationsScreen.kt`)

The Android application provides:
1. **Tab Switcher**: Toggle between `Event Rules` and `Scheduled Tasks`.
2. **Add Rule Modal**: Create new event-triggered rules with custom trigger and action selections.
3. **Toggle & Delete Controls**: Enable/disable rules with switch widgets, delete with trash icon.
4. **Live Verification**: Rules saved on the mobile device immediately persist to the Linux host's SQLite database and update the live rules count.
