# Regnant v1.2 — Persistent Remote Terminal
## Native PTY Sessions, Circular Output Buffer & Mobile Auxiliary Keyboard

Regnant v1.2 integrates an interactive pseudo-terminal subsystem that allows developers to run shell commands, interact with interactive curses utilities (`htop`, `vim`, `nano`, `git log`), and control build scripts directly from their Android device.

---

## 1. Native PTY Architecture

Located in `linux/host/src/terminal/manager.js`:

- **PTY Engine**: Powered by `node-pty`, compiling directly against Linux POSIX pseudo-terminal primitives (`posix_openpt`, `grantpt`, `unlockpt`).
- **Shell**: Resolves the user's default login shell (`$SHELL`, fallback `/bin/bash`), initialized with user environment variables (`TERM=xterm-256color`, `COLORTERM=truecolor`, `HOME=/home/roonakyadav`).
- **Working Directory**: Defaults to the user's home directory (`/home/roonakyadav`) or a chosen project path.
- **Process Management**: Child processes run under the user's desktop session privileges, isolated from arbitrary remote shell execution because input passes through a live interactive PTY fd rather than arbitrary `child_process.exec()` string evaluation.

---

## 2. Multi-Session Registry & Circular Buffer

- **Session Registry**: Manages concurrent named terminal sessions keyed by `sessionId` (`term-<timestamp>-<hash>`).
- **Circular Output Buffer**:
  - Each terminal maintains an in-memory rolling buffer of **100 KB** (102,400 bytes).
  - When new data arrives from the PTY fd, it is appended to the buffer and sliced to retain the latest 100 KB:
    ```javascript
    session.buffer = (session.buffer + data).slice(-MAX_BUFFER_BYTES);
    ```
  - Allows mobile clients reconnecting after backgrounding or Wi-Fi roaming to instantly restore the full screen history without loss of scrollback.
- **WebSocket Streaming**:
  - When PTY outputs data, it emits a `data` event which the host server broadcasts via WebSocket as `TERM_DATA`:
    ```json
    {
      "type": "TERM_DATA",
      "sessionId": "term-1794914000",
      "data": "user@electron:~$ "
    }
    ```

## 3. Auxiliary Virtual Keyboard (`TerminalScreen.kt`)

Standard touch keyboards on Android lack critical workstation terminal keys. Regnant provides a dedicated auxiliary horizontal touch bar positioned directly above the software keyboard:

| Key | Byte / Escape Sequence Transmitted |
| :--- | :--- |
| **Tab** | `\t` (Command completion & indentation) |
| **Ctrl** | Toggle modifier for subsequent keypresses |
| **Esc** | `\u001b` (Vim normal mode, cancel dialogs) |
| **Ctrl+C** | `\u0003` (SIGINT - interrupt active process) |
| **Ctrl+D** | `\u0004` (EOF / exit shell) |
| **↑** | `\u001b[A` (Previous shell history) |
| **↓** | `\u001b[B` (Next shell history) |
| **←** | `\u001b[D` (Cursor left) |
| **→** | `\u001b[C` (Cursor right) |

## 4. REST & WebSocket Endpoints

- `GET /api/v1/terminal/sessions`: List active terminal sessions and their metadata.
- `POST /api/v1/terminal/create`: Spawn a new PTY session.
  ```json
  { "cols": 80, "rows": 24, "cwd": "/home/roonakyadav/Projects/regnant" }
  ```
- `GET /api/v1/terminal/buffer?sessionId=<id>`: Retrieve the 100KB scrollback buffer.
- `POST /api/v1/terminal/close`: Terminate the PTY session.
- `POST /api/v1/terminal/input`: Fallback REST input endpoint when WebSocket is transitioning.
- `WebSocket TERM_INPUT`: Send raw key sequences:
  ```json
  { "type": "TERM_INPUT", "sessionId": "term-1794914000", "data": "ls -la\n" }
  ```
- `WebSocket TERM_RESIZE`: Update PTY window dimensions:
  ```json
  { "type": "TERM_RESIZE", "sessionId": "term-1794914000", "cols": 100, "rows": 30 }
  ```
